# Foundations: CI on every pull request

## Business Value
As the developer, I want every PR restored, format-checked, built and tested before it can merge, so that `main` is always releasable.

## Description
**Context:**
`main` is unprotected: PR #1 was squash-merged with no checks. Sprint 1's learning target includes reading and changing a GitHub Actions workflow and explaining what a required check protects ([LEARNING-PATH.md](../LEARNING-PATH.md)).

**Scope:**
- Public GitHub repo `NawarAli1912/SlotDrop`: exists since the skeleton story
- `.github/workflows/ci.yml`: `pull_request` + `push` to `main`, stale PR runs cancelled; one job `build-test` on `ubuntu-latest`: checkout@v7 → setup-dotnet@v6 (global.json, cache on `**/packages.lock.json`) → `restore --locked-mode` → `format --verify-no-changes --no-restore` → `build -c Release` → `dotnet test --solution SlotDrop.slnx --no-build -c Release`; `permissions: contents: read`
- Test results: step logs only
- Repo settings: squash merge only, delete head branches on merge
- Ruleset on `refs/heads/main`, created by `gh api` once `build-test` has reported on the CI PR: PR required (0 approvals, squash only), `build-test` required from GitHub Actions (integration 15368), strict up to date, no force push, no deletion, no bypass (owner included)
- Tests run on Microsoft Testing Platform (xunit.v3 4.x on .NET 10): `dotnet test --solution`; `--logger trx` does not work ([Skeleton tool facts](../tickets/09-skeleton-tool-facts.md) §3)

**Out of Scope, Known Limitations:**
- Deploys: Sprint 2
- Container-based integration tests: the walking-skeleton story adds them to the same job
- Job summary or check-run test reports: when failures get hard to find (first candidate: MTP `--report-gh`)
- Pinning actions to SHAs, Dependabot: "CI: dependency and image scanning"
- A red PR proving the ruleset blocks merges: Nawar chose to trust the settings
- The ruleset as a file in the repo: nothing would apply it; settings as code start with Terraform in Sprint 2

**Test Scenarios:**
- PR into `main`: `build-test` runs and passes
- Merge to `main`: `build-test` runs on the squash commit
- `gh api repos/NawarAli1912/SlotDrop/rulesets/<id>`: shows PR, required `build-test` (integration 15368), strict, squash only, no force push, no deletion, empty bypass list
- Second run: NuGet cache restored
- Format violation: format step fails
- Package change without lock update: `restore --locked-mode` fails
- New push to an open PR: the older run is cancelled

## Functional Acceptance Criteria
**Nominal Use Cases:**
When a PR targets `main`, `build-test` must run and report; the PR must only be mergeable (squash only) once `build-test` is green and the branch is up to date with `main`. A merge must run `build-test` on `main` and delete the head branch.

**Corner Cases:**
- Format violation: the format step fails and the PR can't merge
- Package added without updating `packages.lock.json`: `restore --locked-mode` fails
- A new push while a PR run is in progress: the old run is cancelled

## Technical Acceptance Criteria
- Code Review, including the Secure Code Review Checklist
